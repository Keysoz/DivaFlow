# Changelog

All notable changes to the Diva platform. The format follows Keep a Changelog; versions track the specification (`docs/00-index.md`).

## [Unreleased]

### Fixed
- EOD shift report print fixed: the `POS Next EOD Report` format queried the non-existent `POS Profile.address`, so printview failed with `Unknown column 'address'` and the POS showed the generic “EOD report did not print” warning. The format now uses `company_address` + the Address line, and the warning includes the actual print error. Tracked POS Next patch **0014**; closed-shift print preview verified (HTTP 200, END-OF-DAY REPORT).
- POS Next custom popups (Settings, Product/Promotion Management, Stock Lookup, Invoice Management, Edit Item, Partial Payments) now close with **Escape**; the POS stays usable. Recorded as tracked POS Next patch **0013**; frappe-ui dialogs already closed on Escape. Verified in the running POS with a headless browser.
- Selling dashboard crash on ERPNext 16.52.1 (`Item-wise Sales History` received `company=None`): the idempotent config now sets `Global Defaults.default_company` to `Diva Dev`, which the chart's dynamic company filter reads. No standard chart/dashboard or core edit. Verified the dashboard loads in a headless browser.

### Changed
- DEC-96 (dev): stock is kept in **Dozen** for new items (UOM conversion Dozen = 1, Nos = 1/12; existing items with history keep their UOM). Generated internal EAN-13 barcodes carry **type EAN-13 and UOM Dozen**, and the primary barcode stays on the Item so the list shows it. The Item list replaces **Opening Stock** with **Left stock** (total Bin qty, via `diva_guard.item_list.left_stock`) and shows the barcode; the Barcode Type column is visible. Item -> Add Item opens the standard quick entry with **Edit Full Form**, and the quick-entry fields (barcode, selling price, UOM) are visible in the full form. **Print** buttons added to Purchase Invoice and Sales Invoice. The rules-engine MOQ now converts `stock_qty` by the item's stock UOM. A backfill copies the first child barcode into `custom_barcode` for existing items (53 on the dev site).
- ENH-E-05 follow-up (dev, DEC-90): **EGP is the system currency** — `Global Defaults.default_currency = EGP`, so ERPNext no longer tries an INR -> EGP exchange-rate lookup on every document (previously "Unable to find exchange rate for INR to EGP ... create a Currency Exchange record manually") and prints no longer show the rupee symbol. **Item creation moved to the Item module**: the PR/SI "Add New Item" button opens ERPNext's standard Item quick entry, and the Item list "Add Item" opens a Diva dialog (code, name, group, barcode, accepted quantity per Dozen, warehouse, buying price per Dozen, Standard Selling + Wholesale prices) that creates the Item and a **submitted Stock Reconciliation** posting the opening quantity as Nos at buying price / 12, with the Temporary Opening account. A blank barcode on any new stock Item now auto-generates an internal EAN-13, and new stock items default to Dozen purchase/sales UOM. **No auto-submit**: the Purchase Receipt now creates its Purchase Invoice and Material Transfer to Stores - DD as **drafts** for the owner to submit, and the Sales Invoice custom **Print button is removed** (standard Menu -> Print remains). In the items grid, **Tab moves cell to cell inline** and the full row editor opens only from the pin icon; the row editor hides tax, discount, weight, manufacture, reference and deferred sections. Tests: `scripts/test_desk_workflows.py` all pass (standard item auto-barcode, opening-stock item + 24 Nos valuation 75, search, draft PR follow-ups submitted manually, Pay partial/full); headless Chromium checks pass (Item dialog, standard quick entry, inline Tab, simplified row editor, no SI Print button); `make lint test` green; config re-run 0 changes.

### Added

New client-only app **`diva_desk`** (`app_include_js`, no doctypes) loads a thin Desk layer: Purchase Receipt focuses the supplier, Tab moves to the accepted warehouse and then into the item row, an **Add New Item** dialog creates the item with a generated internal EAN-13 and prints a 50×30 mm label (code, name, barcode); Sales Invoice focuses the customer and Tab jumps to the item row; any other Link field accepts the first suggestion on Tab when it has text. Shortcuts: F1 help, F2 party, F3 item, F8 pay, F9 print, Ctrl+S save, Ctrl+Enter submit. `diva_guard.desk_api` adds the server half: **Add New Item** (Nos stock UOM, Dozen buying/selling, Standard Selling prices, duplicate/valid EAN-13 checks), **Pay** (full or partial, Cash by default, creates and submits the Payment Entry only on click, company-currency invoices only, audit comment), **Desk search** (Items by code/name/group/barcode, Customers/Suppliers by id/name/phone on the linked Contact, Sales Invoices by id, exposed through the `awesomebar_search` hook) and the **Purchase Receipt on_submit** automation: Purchase Invoice via ERPNext's `make_purchase_invoice` with `update_stock=0` and a Material Transfer of each line's stock quantity to **Stores - DD** when the accepted warehouse differs, both idempotent, failures logged and shown. Config: `set_warehouse` defaults to Stores - DD and is labelled "Accepted Warehouse", put-away/posting-time hidden, Payment Entry mode defaults to Cash, Item Opening Stock removed from quick entry (DEC-88). Report print formats: one Diva format named after each main report (AR, AP, General Ledger, Trial Balance, P&L, Balance Sheet, Stock Balance, Stock Ledger) plus the bespoke Party Statement, so Frappe prints the Diva layout by default (DEC-89).
